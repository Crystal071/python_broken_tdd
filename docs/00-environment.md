# 00. Окружение на Ubuntu

## Что понадобится

| Что               | Версия            | Зачем                                |
| ----------------- | ----------------- | ------------------------------------ |
| Ubuntu             | 22.04 или новее   | основной дистрибутив курса           |
| `git`             | любой             | работа с репозиторием                |
| `curl`            | любой             | установка `uv`                       |
| Сеть              | нужен один раз    | скачать `uv`, Python и зависимости   |
| Место на диске    | ~1 ГБ             | Python, зависимости, кэш             |

Системный Python **трогать не нужно**: ни `apt install python3.12`, ни
`pip install` в системный интерпретатор. Весь проект живёт в своём
окружении `.venv`, которое создаёт `uv`.

## Быстрый путь

```bash
git clone <url> shop-broken-tdd && cd shop-broken-tdd
./scripts/setup.sh
./scripts/doctor.sh      # убедиться, что всё в порядке
```

`setup.sh` идемпотентен: его можно запускать сколько угодно раз, он сначала
проверяет, что уже стоит, и докачивает только недостающее. Он ставит:

1. `uv` — если его нет (официальным установщиком, в `~/.local/bin`);
2. Python 3.12 — через `uv python install`, системный Python не трогает;
3. зависимости проекта — `uv sync`, создаёт `.venv` в корне репозитория.

Проверка без установки (тот самый режим, который использует CI):

```bash
./scripts/setup.sh --check    # код 0 — окружение готово, код 1 — нет
```

## Ручной путь

Полезно знать, что делает скрипт. Все команды выполняются из корня репозитория.

```bash
# 1. Базовые пакеты
sudo apt update
sudo apt install -y git curl

# 2. uv — менеджер Python и зависимостей
curl -LsSf https://astral.sh/uv/install.sh | sh

# 3. Если новый терминал всё ещё не видит uv
export PATH="$HOME/.local/bin:$HOME/.cargo/bin:$PATH"
# и добавьте ту же строку в ~/.bashrc, чтобы не повторять
uv --version

# 4. Python версии 3.12
uv python install 3.12

# 5. Зависимости проекта и виртуальное окружение
uv sync

# 6. Проверка
uv run python --version   # Python 3.12.x
uv run pytest -v
```

## Что такое `uv` и `.venv` в двух абзацах

`uv` заменяет сразу несколько привычных инструментов: `pip`, `venv` и частично
`pyenv`. Он читает `pyproject.toml`, создаёт рядом с проектом каталог `.venv`
(виртуальное окружение — изолированная копия интерпретатора с библиотеками
проекта) и запоминает точные версии пакетов в файле `uv.lock`.

Ключевая привычка: **не пишите `pip`, пишите `uv run`**. Команда `uv run pytest`
означает «запустить `pytest` внутри окружения проекта». Системные пакеты при этом
не появляются, ничего не ломается глобально.

## Как выглядит успех

```bash
$ uv --version
uv 0.12.19 (...)

$ uv run python --version
Python 3.12.14

$ ./scripts/doctor.sh
  успех  git установлен
  успех  uv не старше 0.9.0
  ...
Окружение готово к работе.
```

Проверки сборки на этом шаге падают — так и задумано, репозиторий приходит в
красном состоянии. Разбор красного вывода — в [part1-red-ci.md](part1-red-ci.md).

## Редактор

Чтобы редактор видел то же окружение, выберите интерпретатор
`.venv/bin/python` (VS Code: `Python: Select Interpreter` → путь в корне проекта).
Полезные расширения VS Code: Ruff, Python (Pylance), GitHub Actions.
